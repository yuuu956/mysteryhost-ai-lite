# Evaluation Metrics: MysteryHost AI Lite

本文件记录 MysteryHost AI Lite 的 AI 评测指标设计。

本项目的评测目标不是单纯判断 AI 回答是否“像人”，而是判断 AI 主持人是否能够在剧本杀推理场景中稳定、可控、有效地完成主持人任务。

## 1. Evaluation Goal

MysteryHost AI Lite 的评测目标包括：

1. 用户是否能顺利完成完整推理流程。
2. 主持人回答是否符合当前游戏阶段。
3. 主持人是否避免提前剧透。
4. 主持人是否避免编造不存在的线索。
5. 线索释放是否有节奏感。
6. 推理复盘是否清晰、有依据。
7. 项目是否能体现 AI 产品经理的产品设计能力。

## 2. Product Experience Metrics

### 2.1 Game Completion Rate

定义：

> 用户从进入页面到完成最终推理复盘的比例。

评估路径：

```text
查看案件背景
→ 阅读角色卡
→ 释放全部线索
→ 向主持人提问
→ 提交最终推理
→ 查看复盘结果
```

意义：

该指标用于判断产品流程是否完整、清晰、可完成。

---

### 2.2 Clue Release Completion Rate

定义：

> 用户是否完成 Round 1 到 Round 3 的全部线索释放。

评估方式：

* 用户是否点击“释放下一轮线索”
* 用户是否查看全部三轮线索
* 用户是否理解线索逐步推进的关系

意义：

如果用户没有继续释放线索，可能说明线索不够吸引人，或者页面引导不够清晰。

---

### 2.3 Host Q&A Interaction Rate

定义：

> 用户是否使用主持人问答功能。

评估方式：

* 是否输入问题
* 是否完成至少一次提问
* 是否连续提问多个角色或线索

意义：

该指标用于判断 AI 主持人是否对用户有实际价值。

---

### 2.4 Reasoning Submission Rate

定义：

> 用户是否愿意提交最终推理。

意义：

这是判断游戏是否形成闭环的重要指标。

如果用户不提交推理，说明游戏动机、线索设计或复盘吸引力可能不足。

## 3. AI Host Quality Metrics

### 3.1 Relevance

定义：

> 主持人回答是否与玩家问题相关。

示例：

玩家问：

```text
沈念有什么问题？
```

合格回答应围绕：

* 沈念和死者的关系
* 她掌握的财务文件
* 她是最后见过死者的人之一
* 她的证词是否可疑

不合格回答：

```text
请继续关注现场线索。
```

原因：

该回答过于泛泛，没有回应玩家具体问题。

---

### 3.2 Groundedness

定义：

> 主持人回答是否基于当前案件数据和已释放线索。

主持人回答可以基于：

* 案件背景
* 角色卡
* 当前回合
* 已释放线索
* 玩家问题

主持人回答不应基于：

* 未释放线索
* 完整真相
* 代码中不存在的新角色
* 模型自行编造的信息

---

### 3.3 Consistency

定义：

> 主持人回答是否与已有设定保持一致。

需要检查：

* 角色身份是否一致
* 死者信息是否一致
* 案发地点是否一致
* 线索内容是否一致
* 凶手和真相是否没有被提前改写

---

### 3.4 Usefulness

定义：

> 主持人回答是否能帮助玩家继续推理。

好的回答不应直接给出答案，而应引导玩家关注：

* 时间线
* 动机
* 现场证据
* 人物关系
* 证词矛盾

---

### 3.5 Tone Fit

定义：

> 主持人回答是否符合剧本杀主持人口吻。

合格语气应具备：

* 简洁
* 有悬疑感
* 不过度解释
* 不替玩家直接推理
* 不嘲讽玩家

## 4. Risk Control Metrics

### 4.1 Spoiler Rate

定义：

> 主持人在不该剧透时提前透露最终真相的比例。

剧透行为包括：

* 提前说出凶手
* 提前说明完整作案方式
* 使用尚未释放的关键线索
* 直接告诉玩家最终答案

目标：

```text
Spoiler Rate = 0
```

---

### 4.2 Hallucination Rate

定义：

> AI 编造不存在角色、线索、地点或剧情的比例。

幻觉示例：

* 编造不存在的角色
* 编造新证据
* 修改死者身份
* 修改凶手
* 添加未定义地点

控制方式：

* 只基于结构化案件数据回答
* Host Q&A Prompt 不传入 truth
* 输出后检查实体是否存在于案件数据中

---

### 4.3 Unsupported Answer Rate

定义：

> 主持人给出没有上下文依据回答的比例。

示例：

玩家问：

```text
周遥有没有修改系统？
```

如果当前已释放线索中尚未出现系统日志，主持人不应直接确认。

更合适的回答是：

```text
目前线索不足以直接确认周遥是否修改系统，但他的技术能力确实值得关注。
```

---

### 4.4 Refusal Accuracy

定义：

> AI 是否能在应该拒答时正确拒答。

应该拒答的问题包括：

* 谁是凶手？
* 直接告诉我真相。
* 最终答案是什么？
* 后面还会出现什么关键线索？

合格回答应拒绝直接透露，并引导玩家继续推理。

## 5. Reasoning Review Metrics

### 5.1 Murderer Identification Accuracy

定义：

> 系统是否正确判断玩家是否指出真正凶手。

在当前剧本中，真正凶手是：

```text
沈念
```

如果玩家推理中提到沈念，应识别为命中关键嫌疑人。

---

### 5.2 Motive Coverage

定义：

> 玩家是否解释作案动机。

当前剧本中的核心动机包括：

* 财务报销
* 举报邮件
* 阻止许言提交证据

如果玩家提到这些内容，应提高评分。

---

### 5.3 Timeline Analysis Coverage

定义：

> 玩家是否分析时间线问题。

关键内容包括：

* 监控中断
* 签到记录
* 死亡时间
* 不在场证明

---

### 5.4 Evidence Usage

定义：

> 玩家是否使用关键现场证据。

关键证据包括：

* 墨水痕迹
* 消防通道纤维
* 未发送举报邮件草稿
* 被修改的会议室签到记录

---

### 5.5 Feedback Explainability

定义：

> 复盘结果是否解释了为什么得出该评分。

好的复盘不只是给分，还应该说明：

* 命中了哪些点
* 遗漏了哪些点
* 哪些证据支持结论
* 哪些推理仍然不足

## 6. Test Cases

### 6.1 Host Q&A Test Cases

| User Question | Expected Behavior |
| ------------- | ----------------- |
| 我可以调查图书馆现场吗？  | 回答现场相关信息，不剧透      |
| 沈念有什么问题？      | 回答沈念可疑点，但不直接说她是凶手 |
| 林舟是不是凶手？      | 提醒有动机但证据不足        |
| 周遥是不是帮凶？      | 说明其具备系统能力，但不能直接定罪 |
| 现在可以知道真相吗？    | 拒绝直接透露真相，引导继续推理   |

## 7. High-score Reasoning Example

```text
我认为凶手是沈念。她因为财务报销和举报邮件的问题想阻止许言，并利用监控中断和签到记录制造不在场证明。现场的消防通道纤维和墨水痕迹说明她伪造了现场。
```

期望表现：

* 正确指出凶手
* 解释财务动机
* 提到监控和签到记录
* 使用现场证据
* 应获得较高评分

## 8. Low-score Reasoning Example

```text
我觉得是林舟，因为他看起来最可疑。
```

期望表现：

* 没有指出真正凶手
* 证据不足
* 没有解释时间线
* 没有使用现场证据
* 应获得较低评分

## 9. Evaluation Checklist

### 9.1 Host Q&A Checklist

* [ ] 回答是否相关？
* [ ] 是否只使用已释放线索？
* [ ] 是否没有提前透露凶手？
* [ ] 是否没有编造新线索？
* [ ] 是否符合主持人口吻？
* [ ] 是否能引导玩家继续推理？

### 9.2 Reasoning Review Checklist

* [ ] 是否识别玩家指出的凶手？
* [ ] 是否识别玩家提到的动机？
* [ ] 是否识别玩家使用的关键证据？
* [ ] 是否指出遗漏点？
* [ ] 是否给出合理评分？
* [ ] 是否解释最终真相？

### 9.3 Script Generation Checklist

* [ ] 剧情是否完整？
* [ ] 凶手是否在角色列表中？
* [ ] 关键证据是否在线索中出现？
* [ ] 三轮线索是否逐步推进？
* [ ] 真相是否能被线索推导？
* [ ] 是否避免过度血腥或不适内容？

## 10. Summary

MysteryHost AI Lite 的评测体系重点关注：

* 产品流程是否完整
* AI 主持人是否有用
* AI 主持人是否不剧透
* AI 是否避免幻觉
* 复盘是否有解释性
* 输出是否符合结构化要求

本项目的评测思路体现了 AI 产品经理的核心能力：

> 不只关注模型能否生成内容，还要关注生成内容是否符合场景、是否可控、是否可评估、是否能稳定进入产品流程。
