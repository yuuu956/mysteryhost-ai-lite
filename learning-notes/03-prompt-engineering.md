# 03 Prompt Engineering

本笔记用于记录我对 Prompt Engineering 的基础理解，并结合 MysteryHost AI Lite 项目分析 Prompt 如何帮助 AI 产品获得更稳定、可控、可复用的输出。

## 1. 什么是 Prompt Engineering？

Prompt Engineering 是指通过设计输入指令、上下文、约束条件和输出格式，引导大语言模型完成特定任务的方法。

从 AI 产品经理视角看，Prompt 不只是“给 AI 写一句话”，而是一种产品设计手段。

一个好的 Prompt 需要回答：

* AI 扮演什么角色？
* AI 要完成什么任务？
* AI 可以基于哪些信息回答？
* AI 不允许做什么？
* AI 应该用什么格式输出？
* AI 在不确定时应该如何处理？

在 MysteryHost AI Lite 中，Prompt 的作用是让 AI 像一个合格的剧本杀主持人，而不是随意聊天或随意编故事。

## 2. 为什么 AI 产品需要 Prompt Engineering？

大语言模型本身具有开放性，优点是灵活，缺点是不稳定。

如果没有 Prompt 约束，AI 可能会：

* 输出格式不一致
* 回答过长或过短
* 编造不存在的信息
* 提前泄露最终真相
* 忽略当前游戏阶段
* 不遵守产品规则

Prompt Engineering 的目标，就是把模型的开放生成能力，变成更稳定、更符合产品目标的输出。

## 3. 一个基础 Prompt 的组成

一个较完整的 Prompt 通常包含以下部分：

| 组成部分          | 作用               |
| ------------- | ---------------- |
| Role          | 定义 AI 扮演的角色      |
| Task          | 定义 AI 需要完成的任务    |
| Context       | 提供必要背景信息         |
| Constraints   | 规定 AI 不能做什么      |
| Output Format | 规定输出格式           |
| Examples      | 提供示例，帮助模型学习格式和风格 |

## 4. Role Instruction：角色设定

Role Instruction 用于告诉模型它是谁。

例如，在 MysteryHost AI Lite 中，AI 的角色不是普通聊天助手，而是：

```text
你是一个文字版剧本杀游戏的 AI 主持人。
你负责管理剧情、释放线索、回答玩家问题和进行最终推理复盘。
```

角色设定越明确，AI 的回答风格和行为边界就越稳定。

## 5. Task Description：任务描述

Task Description 用于告诉模型这次具体要做什么。

例如：

```text
请根据当前案件背景、已释放线索和玩家问题，生成一段主持人回答。
```

或者：

```text
请根据玩家的最终推理，分析其命中点、遗漏点，并输出复盘结果。
```

任务描述需要具体，不要只写“帮我分析一下”。

## 6. Context Injection：上下文注入

Context Injection 是指把任务需要的信息传给模型。

在 MysteryHost AI Lite 中，主持人回答玩家问题时，需要注入：

* 案件背景
* 当前回合
* 已释放线索
* 角色公开信息
* 玩家问题
* 防剧透规则

不应该注入：

* 尚未释放的关键线索
* 最终凶手
* 完整真相
* 与当前问题无关的长篇内容

这样可以减少模型误用信息和提前剧透。

## 7. Constraint Design：约束设计

约束是 Prompt 中非常重要的部分。

在 MysteryHost AI Lite 中，主持人问答 Prompt 需要设置以下约束：

1. 不得提前透露最终凶手。
2. 不得编造当前剧本中不存在的线索。
3. 不得使用尚未释放的线索。
4. 不得替玩家直接给出完整推理答案。
5. 如果玩家询问真相，应进行引导而不是直接回答。
6. 回答应简洁、有悬疑感，并符合主持人口吻。

示例：

```text
如果玩家询问“谁是凶手”或“真相是什么”，你不能直接回答。
你应该提醒玩家继续关注时间线、动机和现场证据。
```

## 8. Output Format：输出格式控制

AI 产品中，模型输出不能只是一大段自然语言。

为了让前端页面可展示、可复用，应该尽量要求结构化输出。

例如角色卡生成可以要求：

```json
{
  "name": "角色名",
  "identity": "身份",
  "publicInfo": "公开信息",
  "secret": "隐藏秘密",
  "relationship": "与死者关系",
  "suspicion": "可疑点"
}
```

推理复盘可以要求：

```json
{
  "score": 80,
  "level": "接近真相",
  "hitPoints": ["指出凶手", "提到财务动机"],
  "missedPoints": ["未解释监控中断"],
  "summary": "整体推理方向正确，但仍缺少关键证据链。"
}
```

结构化输出的价值是：

* 前端更容易渲染
* 结果更容易保存
* 更方便做评测
* 更容易发现错误
* 更适合作为产品功能使用

## 9. Few-shot Examples：示例提示

Few-shot 是指在 Prompt 中提供一个或几个示例，让模型模仿格式和风格。

例如：

```text
玩家问题：林舟是不是凶手？
主持人回答：目前不能直接确认。林舟确实有经济动机，但请注意，动机并不等于作案能力。你还需要关注时间线是否被人为修改。
```

示例可以帮助模型学习：

* 回答长度
* 语气风格
* 拒答方式
* 引导方式
* 信息边界

## 10. Prompt 在 MysteryHost AI Lite 中的应用

本项目后续至少需要三类 Prompt。

### 10.1 剧本生成 Prompt

用于根据主题、人数和难度生成案件背景、角色和线索。

需要控制：

* 剧情完整
* 人物动机清楚
* 线索和真相一致
* 不要过度复杂
* 输出结构化 JSON

### 10.2 主持人问答 Prompt

用于根据当前回合和已释放线索回答玩家问题。

需要控制：

* 不提前剧透
* 不编造线索
* 只基于当前上下文回答
* 保持主持人口吻
* 对真相类问题进行引导

### 10.3 推理复盘 Prompt

用于根据玩家推理和最终真相输出复盘。

需要控制：

* 判断命中点
* 指出遗漏点
* 给出评分
* 解释依据
* 最后揭示真相

## 11. 当前 MVP 中的 Prompt 思维

当前 MysteryHost AI Lite 暂未接入真实 LLM API，但已经使用了 Prompt Engineering 的产品思想。

例如：

* 主持人问答中设置了“不能提前透露真相”的规则。
* 回答根据玩家问题关键词选择不同回应。
* 当前回合小于 3 时，会提醒玩家“部分关键信息尚未公开”。
* 推理复盘使用固定字段输出评分、命中情况、遗漏点和最终真相。

这些本地规则，后续都可以转化为 Prompt 和工具调用逻辑。

## 12. AI 产品经理需要关注的 Prompt 问题

设计 Prompt 时，AI 产品经理需要关注：

1. Prompt 是否对应真实产品场景？
2. 输入上下文是否足够但不过量？
3. 输出格式是否可被前端使用？
4. AI 是否有明确禁止事项？
5. AI 不知道时是否会拒答？
6. AI 是否可能泄露不该泄露的信息？
7. Prompt 是否方便版本迭代？
8. Prompt 是否可以被评测？
9. Prompt 是否会导致成本过高？
10. Prompt 是否能覆盖边界情况？

## 13. 阶段性总结

Prompt Engineering 是 AI 产品经理必须掌握的基础能力。

它的本质不是写“神奇咒语”，而是通过角色、任务、上下文、约束和输出格式，把模型能力纳入产品流程。

在 MysteryHost AI Lite 中，Prompt 的核心价值是：

> 让 AI 主持人在互动推理游戏中既能生成有趣内容，又能遵守游戏阶段、控制信息边界、防止剧透，并输出可被页面使用的结构化结果。
